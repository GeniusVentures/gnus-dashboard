## Languages

## Protobuf Generation

**Generator:** `protobuf-ts` (`@protobuf-ts/plugin` 2.9.4 in `package.json`). The generated files state `@generated by protobuf-ts 2.9.4` or `2.11.1` in their headers, so two plugin versions were used.

**Runtime:** `@protobuf-ts/runtime` (imported by all generated files). `@bufbuild/protobuf ^1.8.0` and `@bufbuild/protoc-gen-es ^1.8.0` are also declared in `dependencies`, but no app code imports them.

**Sources:**
- `.proto` schemas present in repo: `data/protobuf/SGBlocks.proto`, `SGTransaction.proto`, `bcast.proto`, `broadcast.proto`, `delta.proto`, `message.proto`
- Generated TypeScript: `data/protobuf/*.ts` (for the same six schemas), `data/protobuf/crdt/{bcast,delta,heads}.ts` and `data/protobuf/processing/SGProcessing.ts`. The `crdt/` and `processing/` files have no `.proto` in this repo.
- Upstream of the `crdt/` and `processing/` files is the SuperGenius project. Commit `0156529` ("Regenerated TypeScript protobuf files from updated .proto in SuperGenius develop branch") added those four files, 1919 lines in total.

Details of the messages are in INTEGRATIONS.md.

## Configuration

**Environment variables:**
- Only one application-level env var is read: `process.env.baseURL` in `pages/_app.tsx`. It builds the canonical/OG URL. It is not a `NEXT_PUBLIC_` variable, so it is undefined in client bundles unless Next inlines it. Verify in the build before relying on it.
- `NODE_ENV` is read in `__tests__/e2e/basic-smoke.test.js` only.
- `.env` files are gitignored (`.gitignore` lines 75-80). None are tracked. Dotenv is loaded in `_app.tsx`, so a local `.env` would be read if one exists.
- Deploy secrets are GitHub Actions secrets, not app env vars. See INTEGRATIONS.md.

**Hardcoded configuration (not env-driven):**
- `config/config.ts` - Metadata, WalletConnect/Reown project ID (`reown.projectId`), contract addresses (`amoyContract`, `sepoliaContract`), networks `sepolia` (chainId 11155111) and `amoy` (chainId 80002), RPC URLs, explorer URLs
- `app.config.js` and `app.config` - App name, version `0.0.1`, theme skin `light`
- `data/dev_config.json` - Keys: `Address`, `Cut`, `TokenValue`, `TokenID`, `WriteDirectory` (values not recorded here)
- `data/secure_storage.json` - Contains a `GeniusAccount` key. Its value is not recorded here.
- `data/ipfs/bootstrapConfig.ts` - IPFS bootstrap multiaddrs (only the public IP multiaddrs are active, the rest are commented). Not imported by `functions/ipfs/node.ts`.

## Platform Requirements

**Development:**
- Node.js (version not pinned, use a current LTS)
- Yarn Classic (bundled via `.yarn/releases/yarn-classic.cjs`)
- `yarn` then `yarn dev`. Start from the repo root: `functions/ipfs/node.ts` resolves `data/GeniusSDK.dll` against `process.cwd()`.
- A Windows x64 environment is needed to run the native SDK. On other platforms the SDK load fails at module import (see INTEGRATIONS.md).

**Production:**
- Ubuntu host (`runs-on: ubuntu-latest` for the CI job, the target is an AWS EC2 instance reached over SSH). See `.github/workflows/aws-ec2-deploy.yml`.
- Process manager: PM2 (process name `gnus-dashboard`). Build step is `yarn run build`, and the process is restarted with `pm2 restart gnus-dashboard`.
- Note: the deploy flow runs `yarn run build` and then `pm2 restart`. The repo does not contain a `pm2` ecosystem file, so the PM2 process is defined on the server.
